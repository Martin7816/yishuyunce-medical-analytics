# 页面覆盖说明

本文件把十个现有路由映射到 Master 设计系统。页面仍由现有 Vue 路由、`AnalysisPage`、`AnalyticsChart`、`MetricCard` 和 `PageState` 承载；表中的 `grouped_bar`、`scatter`、`heatmap` 是供 #106/#107 使用的可视化候选，不表示本 Issue 已经修改 renderer。

## 1. 统一页面模板

```text
页面顶栏（模块名 / 数据版本 / 生成时间 / fixture 标识）
└─ 页面标题 + 统计对象 + 边界提示
   └─ 白名单筛选（可深链接、可清空、互斥提示）
      └─ KPI（label / value / unit）
         └─ 主图表卡（问题 / 单位 / 图例 / Tooltip / 表格摘要）
            └─ 确定性洞察（来源 metric/section / 边界 / 相关不等于因果）
               └─ 版本、生成时间和下游入口
```

标准模式保持上述完整顺序。大屏模式只改变 `overview` 的栅格、字号和卡片高度；不把其他页面拼进驾驶舱，不增加指标，不在浏览器二次聚合。

## 2. 十路由覆盖矩阵

| 路由 | 面向问题 | 主布局与 section | 筛选/深链接 | 大屏策略 | 必须保留的边界 |
|---|---|---|---|---|---|
| `/overview` | 这批住院出院记录的整体运营结构是什么 | 4–6 个 KPI；年龄、支付方式、医院病例量、严重程度等排行/分布；数据质量状态 | 无业务筛选；从图表进入医院/疾病等深链接时保留来源筛选摘要 | 唯一大屏入口；同一 section 全屏重排 | 病例量按住院出院记录计数，不等于患者数；没有真实时间趋势 |
| `/hospitals` | 不同医疗机构的病例量和运营指标如何比较 | 医院索引；双院 KPI；`grouped_bar` 关系对照；表格事实视图 | `facility_a`、`facility_b`、`metric`；两院不能相同 | 大屏只作为从 overview 深链后的标准比较视图，不独立循环 | 以 `facility_id` 聚合，医院名称只展示；不表达机构导致结果 |
| `/diseases` | 哪些主诊断描述的病例量最高，某项画像是什么 | TOP10 横向 bar；疾病画像 KPI/分布；长名称表格 | `diagnosis_code` 来自 `options.diagnoses`；路径 `/diseases/{code}` | 不放入 stage；从医院/风险/费用回到此页时保留 code | 病例量不是患者数/患病人数；主诊断描述为空不参与排行 |
| `/cohorts` | 有限年龄、性别、入院方式组合下的记录结构是什么 | 筛选摘要；病例量 KPI；年龄/性别/入院方式/疾病/严重程度 bar；必要时 `grouped_bar` | `age_group`、`gender`、`admission_type`；仅白名单枚举 | 不放入 stage；筛选后的空结果仍保留边界和版本 | 是住院记录群体，不是患者队列；不做跨次住院连接 |
| `/costs` | 收费、成本、住院时长在不同群体/机构下如何呈现 | 分位数 bar；收费/成本 KPI；`scatter`（收费 × 住院时长聚合关系）；表格 | `diagnosis_code` 与 `facility_id` 互斥，可加 `severity` | 不把 scatter 放进 stage；大屏可从 overview 下钻进入 | `Total Charges` 是账面收费，`Total Costs` 是估算成本；单日金额仅 `los>0` |
| `/risks` | 年龄和病情严重程度的群体结构及风险指标是什么 | 风险 KPI；`heatmap`（年龄 × 严重程度）；severity bar；矩阵表 | `age_group`、`diagnosis_code`；筛选恢复到 URL | 不放入 stage；重点显示边界通知和表格 | 仅群体统计；不构成个人诊断、治疗建议或因果判断；分母是当前筛选记录 |
| `/payments` | 支付方式、年龄结构和收费差异是什么 | 支付方式 bar；年龄 bar；收费对照 table/bar | `payment_type`、`age_group`，来源为 payload options | 不放入 stage；可从 overview 支付 section 深链 | 支付方式来自 `Payment Typology 1`；金额指标只使用可解析非负收费 |
| `/data-quality` | 当前批次和任务依赖是否可追溯 | 状态 card/table；关键字段完整性；四态 | `data_version` 只读当前批次 | 不放入 stage；状态字样必须完整显示 | `CHECK_REQUIRED`/`FIXTURE_ONLY` 不得被视觉改写成真实 PASS |
| `/model` | 高费用记录分类模型的指标和输入边界是什么 | 模型版本/阈值 KPI；指标表；混淆矩阵 table；预测表单 | 固定字段；预测请求拒绝泄漏字段 | 不放入 stage；单独显示模型版本和训练边界 | 运营分析用途，不表示医疗风险；收费等泄漏字段不能成为请求特征 |
| `/assistant` | 如何基于白名单汇总指标生成带来源的回答 | 问题输入；工具轨迹；来源指标/版本/统计边界；错误/重试 | 仅 `message`；不保存历史；结果可深链到来源模块 | 不放入 stage；避免把未验证 AI 文案放入大屏 | 不执行自由 SQL，不访问原始住院明细；上游失败不生成无来源答案 |

## 3. 布局与响应式规则

| 视口 | 页面模板 | 图表行为 | 导航/筛选行为 | 验收关注 |
|---:|---|---|---|---|
| 390px | 单列；标题、边界、KPI、主结论优先 | bar 改横向或减少刻度；scatter/heatmap 先摘要后表格；表格独立滚动 | 菜单按钮打开显式抽屉；筛选控件满宽；每个控件 ≥44px | 无页面级横向滚动，焦点不被抽屉/顶栏遮挡 |
| 768px | KPI 两列；图表按复杂度一/两列 | 图例折行；点位不要求精确点击；表格可横向滚动 | 侧栏可折叠；筛选允许换行 | Tab 顺序与视觉顺序一致，标题不截断 |
| 1024px | 侧栏 224px；内容 8 列 | 图表最小 280px；表头/图例不挤压 | 筛选保持同一顺序 | 关键文案、单位和版本完整 |
| 1440px | 12 列；标准内边距 32px | 主图 320px 左右；复杂图旁置摘要/表格 | 侧栏 240px；大屏模式使用同一内容 | 1440×900 展示稳定，无额外模块 |

## 4. 交互和状态覆盖

- 进入任一分析路由先显示 `loading`，成功后才显示图表；筛选变更时清理旧 section；
- 合法但无数据显示 `empty`，保留筛选、版本、边界和清空动作；
- 非法参数、未发布结果、数据库失败和上游 AI 失败分别保留稳定错误 code/trace/retry 语义；
- 图表点位、图例和可下钻行必须支持键盘等价操作；Tooltip 不能只在 hover 时出现；
- “回到来源页”使用显式链接，浏览器后退恢复筛选和滚动，不把用户重定向到 overview；
- stage 模式退出后回到标准模式，不改变业务筛选和数据版本。
