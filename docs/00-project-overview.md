# 医数云策智慧医疗运营大数据与AI决策分析平台项目概览

## 1. 产品要解决的问题

住院运营数据包含医院、诊断、住院时长、费用、病情严重程度和支付方式等信息。医数云策（正式名称为“医数云策智慧医疗运营大数据与AI决策分析平台”）以统一规则清洗和汇总这些数据，通过网页、分类模型和受控 AI 问答帮助医院运营管理人员与医疗数据分析人员理解群体结构和运营特征。

系统回答“这批住院出院记录呈现什么运营特征”，不回答“某位患者应该怎样诊断或治疗”。SPARCS 数据没有可用于跨记录追踪的患者唯一标识，因此一行统一称为“住院出院记录”，统计数量统一称为“病例量”。

## 2. 数据范围

项目使用老师提供的 2021 年纽约州 SPARCS 去标识化住院出院数据：

- 2,101,588 条住院出院记录；
- 33 个原始字段；
- 数据版本由文件名、文件大小和 SHA-256 共同标识；
- 完整 CSV 作为原始副本保存在 HDFS，不进入 Git；Hive 外部表 `analytics_check.sparcs_2021_raw_issue39` 提供结构化访问；
- 仓库中的固定样例只用于代码、接口和页面联调。

字段核验、缺失情况和全量结果见 [数据与可行性](01-data-and-feasibility.md)。

## 3. 产品模块

| 模块 | 面向的问题 | 页面 |
|---|---|---|
| 运营驾驶舱 | 整体病例量、机构数、住院时长、收费成本和结构分布 | `/overview` |
| 医院运营分析 | 医疗机构排行、机构画像和双院比较 | `/hospitals` |
| 疾病画像分析 | 疾病病例量排行和单病种群体画像 | `/diseases` |
| 住院记录群体分析 | 年龄、性别和入院方式组合下的群体结构 | `/cohorts` |
| 费用与成本分析 | 收费、成本、分位数和不同维度的差异 | `/costs` |
| 病情严重程度与风险分析 | 严重程度、死亡风险和高风险记录结构 | `/risks` |
| 支付方式分析 | 支付方式、年龄结构和收费差异 | `/payments` |
| 数据质量校验 | 分析批次、缺失、异常和任务状态 | `/api/v1/data-quality/summary`（无独立前端页面） |
| 高费用记录分类 | 使用入院时可得字段估计高费用分类 | 后端模型接口（无独立前端页面） |
| AI 问答与洞察报告 | 通过白名单工具读取汇总指标并形成带来源的回答 | `/assistant` |

## 4. 系统组成

```text
HDFS 原始 CSV / Hive 外部表
  → 本地模式 PySpark 读取、清洗与聚合
  → 统一分析快照与模型工件
  → MySQL 服务结果
  → Flask API
  → Vue / D3 SVG
  → 受控 AI 工具
```

- PySpark 负责原始数据清洗、指标聚合和模型训练；
- MySQL 保存小型汇总快照，不保存原始住院明细；
- Flask 只读取已发布结果并执行参数白名单校验；
- Vue 只展示 API 数据，不连接数据库或重算指标；
- AI 只调用登记过的汇总查询工具，不执行自由 SQL，也不保存多轮历史；
- HDFS 和 Hive 负责原始数据存储与结构化访问；PySpark 的清洗、聚合和模型逻辑保持不变，不在 HDFS/Hive 中重复生成第二套正式指标。

系统不包含登录权限、个人诊断、治疗建议、自由 SQL、微服务、Redis、Kubernetes、3D 可视化或本地大模型部署。

## 5. 项目状态

运营驾驶舱、医院、疾病、住院记录群体、费用成本、病情严重程度与风险、支付方式七个分析模块具备真实数据生成、MySQL 发布、API 和页面验收证据。数据质量校验与高费用记录分类保留代码和接口能力，但不再提供独立前端页面；AI 问答保留页面入口，其真实环境结果纳入整体验收。

“代码可运行”“联调快照可展示”和“真实链路验收通过”是三个不同结论：

- 代码可运行：对应模块能够通过自动化测试或构建；
- 联调快照可展示：接口和页面能够用 `fixture:` 数据复现状态；
- 真实链路验收通过：真实 CSV、MySQL、API、页面的字段、单位、排序和数据版本一致，并有可复查证据。

4. 接口开发查看 [API 契约](05-api.md)；
5. 交付前按 [测试与验收](06-test-and-acceptance.md) 留存证据。
