# 医数云策项目五人分工与交接说明

分工表示每名成员对某类结果承担主要质量责任，不表示成员独占目录。所有人围绕同一条数据链协作，并对自己提交的代码、测试、文档和交接信息负责。

## 1. 责任总览

| 成员 | 主要质量责任 | 交付对象 |
|---|---|---|
| 王敬博 | 项目推进、公共契约、Git、集成、部署和展示交付 | 全组、老师与最终运行环境 |
| 魏世轩 | 数据核验、清洗、聚合、模型训练、MySQL 发布和指标核对 | 后端、验收和展示数据 |
| 叶艺鑫 | Flask、快照读取、参数校验、错误语义和 API 联调 | 前端、AI 工具和验收 |
| 李佳明 | Vue、D3 SVG、筛选交互、页面状态和响应式展示 | 用户、验收和答辩演示 |
| 胡钰炜 | 独立核对、端到端验收、问题复验和 AI 事实边界 | 全组、交付证据和展示结论 |

## 2. 王敬博

负责：

- 维护项目范围、公共术语和跨模块契约；
- 把目标拆成有依赖、有负责人、有验收矩阵的 Issue；
- 审查公共字段、环境、端口、目录和安全边界；
- 组织分支集成、组长电脑复现、文档、演示和彩排；
- 在范围、时间和质量冲突时确定取舍。

需要的输入：各角色的实际结果、验证命令、风险和交接条件。

必须交付：可运行的集成分支、统一文档入口、部署与启动流程、最终状态与展示脚本。

## 3. 魏世轩

负责：

- 核验完整 CSV 的字段、行数、缺失、异常和版本；
- 维护统一清洗帧、分析快照、模型工件和独立核对脚本；
- 保证排序、单位、空结果、分位数和实体键符合公共契约；
- 通过事务把完整快照发布到 MySQL；
- 记录真实数据、HDFS、Hive 和 MySQL 的执行证据。

需要的输入：指标契约、模块键、输出 Payload 和数据库权限。

必须交付：数据任务命令、输出摘要、数据版本、独立核对结果、发布与回滚证据。

## 4. 叶艺鑫

负责：

- 通过统一 Repository 和 Service 读取 fixture 或 MySQL 快照；
- 实现路由、参数白名单、响应信封、追踪编号和错误映射；
- 保持合法空结果、模块未发布和依赖失败的语义稳定；
- 保护 SQL、数据库地址、密钥、堆栈和住院明细；
- 为前端与 AI 工具提供可联调接口和示例。

需要的输入：快照表结构、模块键、枚举来源、模型工件和预期响应。

必须交付：接口代码、自动化测试、真实请求摘要、配置说明和下游调用约束。

## 5. 李佳明

负责：

- 实现十个页面路由、公共分析渲染器和必要专用表单；
- 直接展示 API 的指标、分区、单位、版本和时间；
- 实现 loading、success、empty、error、retry 以及请求竞态保护；
- 核对桌面和移动端布局、控制台与可访问性；
- 明确区分联调快照和真实数据。

需要的输入：API 路径、参数、枚举、响应样例、错误码和真实联调地址。

必须交付：页面代码、构建结果、状态与筛选证据、桌面/移动端截图和已知限制。

## 6. 胡钰炜

负责：

- 用独立方法核对数据任务、MySQL、API 和页面的一致性；
- 建立分层验收清单，记录预期、实际、结论和证据；
- 对失败项分配问题、跟踪复验并确认没有回归；
- 验证模型特征、阈值、泄漏边界和真实工件；
- 验证 AI 工具来源、数据版本、超时、错误、断网和医疗边界。

需要的输入：固定样例、真实版本、运行命令、API 契约、页面地址、模型工件和测试密钥。

必须交付：验收矩阵、问题记录、复验结果、端到端证据和最终可陈述结论。

## 7. 交接格式

每次交接写明：

```text
任务 / Issue：
负责人：
提交 / 分支：
输入与数据版本：
交付文件：
运行命令：
实际结果：
验收证据：
依赖与配置：
已知限制：
下游动作：
```

“代码已提交”“本机能跑”或“接口应该可用”不构成交接。接收者必须能够依据交接信息找到输入、执行命令并判断结果。

## 8. 协作边界

- 公共术语、字段、单位、表、API、端口和环境不能由单个角色自行决定；
- 数据层不为页面临时造一套结果，页面不为展示临时重算正式指标；
- 前端和 AI 不直连数据库；
- 验收负责人不替代码作者补齐所有测试；
- 真实数据、凭证和密钥不在交接材料中传播；
- 剩余时间优先用于真实专项验收、集成、文档和彩排。
