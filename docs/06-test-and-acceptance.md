# 医数云策测试与验收

## 1. 验收目标

验收要证明同一批住院运营数据能够经过清洗、聚合、发布、查询和展示，并且各层使用相同的字段、单位、排序、数据版本和统计边界。页面能够打开或自动化测试通过，都不能单独代表真实链路通过。

## 2. 验收层级

| 层级 | 验证对象 | 通过条件 |
|---|---|---|
| L1 数据输入 | 固定样例、完整 CSV、字段和版本 | 行数、字段、年份、缺失和文件指纹可复查 |
| L2 数据任务 | PySpark 快照与模型工件 | 结构合法、运行可重复、独立脚本结果一致 |
| L3 服务结果与 API | MySQL、Flask、参数和错误 | 发布事务完整，接口字段、状态码和错误语义符合契约 |
| L4 页面 | Vue、ECharts、筛选和状态 | 数据原样展示，状态互斥，桌面与移动端无正文溢出 |
| L5 端到端 | CSV → 页面 / AI | 同一版本贯穿各层，真实依赖和失败场景都有证据 |

## 3. 自动化基线

在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pytest backend\tests data\tests -q
cd frontend
npm ci
npm run build
```

自动化测试至少覆盖：

- 统一响应信封与 `X-Trace-ID`；
- GET-only、请求体、未知参数、重复参数和枚举白名单；
- 正常结果、合法空结果、模块未发布、数据库失败和坏快照；
- 费用筛选互斥、实体键顺序和百分比单位；
- 模型请求字段与目标泄漏字段拒绝；
- AI 工具来源、数据版本和上游失败；
- 快照结构校验、事务发布契约和模块独立核对。

## 4. 数据验收

### 4.1 输入

记录以下内容：

- 文件名、大小和 SHA-256；
- CSV 行数、列数和解析异常数；
- `Discharge Year` 范围；
- 数据任务提交号、执行时间和运行环境。

### 4.2 清洗

核对：

- 年份去除首尾空白后等于 `2021`；
- `Length of Stay` 的 `120 +` 映射为 120，并保留截断标记；
- 收费与成本去千分位后解析，负值或非法值不进入金额聚合；
- 编码字段按字符串处理；
- 文本只去除首尾空白；
- 原始记录不按患者去重。

### 4.3 快照

核对每个 `(module_key, entity_key)` 唯一，所有记录共享同一 `data_version` 和 `generated_at`，Payload 只包含契约允许的字段。筛选组合的完整性、空结果、排名顺序和分位数误差按模块独立脚本验证。

### 4.4 模型

核对训练随机种子、阈值来源、训练/测试划分、指标工件和可重复性。特征只允许年龄组、性别、种族、族裔、医院区域、机构编号、入院方式和急诊标志；收费、成本、住院时长、出院去向和出院后字段不得进入训练或预测请求。

## 5. MySQL 与 API 验收

### 5.1 发布

1. 用不带 `--apply` 的命令检查快照；
2. 在测试事务中验证写入与回滚；
3. 使用 `--apply` 发布完整快照；
4. 核对行数、模块数、版本数和时间戳数；
5. 故障注入后确认原批次仍可读。

### 5.2 API

每个接口至少验证：

- 正常请求返回 `200`、`code=OK`、`data` 和 `trace_id`；
- 合法但没有记录的筛选返回 `200` 空结果；
- 非法或未知参数返回 `400`；
- 未发布模块返回 `503 RESULT_NOT_READY`；
- 数据库不可用返回 `503 DATABASE_UNAVAILABLE`；
- 快照损坏返回 `500 SERVICE_RESULT_INVALID`；
- 错误响应不包含 SQL、数据库地址、密码、密钥、堆栈或住院明细。

接口索引和示例见 [API 契约](05-api.md)。

## 6. 页面验收

每个页面验证以下状态：

| 状态 | 预期表现 |
|---|---|
| loading | 显示加载提示，不保留其他筛选条件的旧图表 |
| success | 展示 API 返回的指标、图表、单位、版本和时间 |
| empty | 保留有效筛选与版本信息，指标和图表为空 |
| error | 显示稳定错误提示、错误类型、追踪编号和重试按钮 |
| retry | 依赖恢复后能够重新获得结果 |

还要检查：

- 筛选值来自 API 白名单；
- 页面不聚合、重排、截断或换算正式结果，百分比展示除外；
- 只渲染 `bar`、`pie`、`table`、`status`；
- `fixture:` 版本显示联调提示；
- 1280px 与 390px 视口正文无横向溢出；
- 控制台无未处理错误；
- 图表和表单具备可访问名称。

## 7. AI 验收

使用真实 DeepSeek 密钥和真实汇总快照验证：

- 支持的问题只调用白名单工具；
- 回答包含工具执行过程、来源指标、数据版本和统计边界；
- 回答中的数值能够回查 API；
- 不输出个人诊断、处方或治疗建议；
- 缺少密钥、超时、模型错误和断网时返回真实错误；
- 上游失败时不生成无来源答案；
- 服务不保存多轮对话历史。

## 9. 证据要求

每次验收记录：

- 日期、时区、执行人、分支和提交号；
- 输入文件指纹与数据版本；
- 完整命令和退出码；
- MySQL 行数与事务结果；
- 代表性 API 请求、响应和状态码；
- 页面截图、视口尺寸和控制台结果；
- 预期、实际、PASS/FAIL 与问题编号；
- 下游需要的配置、工件和复现命令。

不得提交完整 CSV、数据库凭证、API 密钥、真实 `.env`、包含住院明细的日志或可反推出敏感信息的工件。
