# M0/M1 最小技术链路与存储边界

> 决策状态：`DECIDED`（2026-08-17）
> 适用范围：第一轮“疾病病例量 TOP10”真实数据闭环
> 关联 Issue：#8、#9、#10、#12、#13

本文只冻结 M0/M1 必须遵守的边界。具体字段名、表名和 API 字段由 #9、#10 继续确认；实际软件版本、端口和组长电脑复现由 #12 核验。没有运行证据的命令标记为“目标命令”，不把它写成已经完成的功能。

## 1. 决策摘要

M1 采用一条可核对的单向链路：本地原始 CSV → Spark 一次清洗与聚合 → 小型服务结果 → MySQL → Flask → Vue/ECharts。Python 标准库脚本负责独立核对，不参与正式服务结果生成。

HDFS、Hive 和 Pandas 不进入当前 M1 的必要链路：它们不是老师材料已经确认的第2组硬性技术，也不能在同一指标上各自再算一遍。若后续老师明确要求其中某项，必须先在对应 Issue 中说明验收价值、输入输出和新增运行成本，再接入现有边界。

## 2. 数据流和唯一事实来源

```text
本地 SPARCS 原始 CSV（唯一原始输入，不进 Git）
                    │
                    ├── Python 标准库独立核对（只验证，不产服务结果）
                    │
                    └── Spark 聚合任务（唯一正式清洗、分组、排序逻辑）
                              │
                              └── 小型 TOP10 结果工件 + 数据版本
                                        │
                                        └── MySQL 服务结果表（API 的唯一事实来源）
                                                  │
                                                  └── Flask 只读 API
                                                            │
                                                            └── Vue + ECharts
```

必须遵守以下规则：

- 原始 CSV 的本地副本是输入事实；完整文件、个人绝对路径和密钥不提交 Git。
- Spark 任务只对 `CCSR Diagnosis Description` 执行 #7 确定的清洗、计数和稳定排序；不在 Pandas、Hive、MySQL、Flask 或前端复制这套计算。
- MySQL 只保存后端需要的 TOP10 小结果，不保存完整住院出院记录，也不接受自由 SQL。
- 结果工件是数据任务到 MySQL 的可复查交接物，不是另一套业务口径；装载成功后 API 仍只查询 MySQL。
- Flask 不重新清洗或聚合，只查询已验证的服务结果；Vue/ECharts 不直连数据库、不计算正式病例量。
- 独立核对必须读取原始输入或固定样本，用与正式任务不同的实现比较结果，不能只查询 MySQL 自证。

| MySQL | M1 服务层必须 | 让 Flask 读取小而稳定的服务结果，并可报告数据库依赖失败 | 输入：已核对的 TOP10 结果工件；输出：服务结果表 | 目标为本地 MySQL，默认端口 3306；表名、字段和刷新事务由 #9 固定 |
| Flask | M1 必须 | 提供受控 HTTP API 和统一错误语义 | 输入：MySQL 服务结果；输出：TOP10 JSON 或明确错误 | 目标默认端口 5000；路径和响应由 #10 固定；Route 不重算指标 |

这里的“病例量”始终是有效住院出院记录数量，不是唯一患者数。数据表的正式字段和类型不能由本表替代，必须以 #9 的契约为准。

## 4. 存储边界与刷新规则

### 4.1 原始数据

完整原始 CSV 只保存在本地指定路径。固定小样本和期望结果可以进入 `data/fixtures/`，用于 M0、契约开发和独立核对。HDFS 当前不作为 M1 的原始数据事实来源；这样可以避免为只有一个输入文件的首版闭环增加 NameNode/DataNode 启动和故障排查成本。

### 4.2 服务结果

M1 只需要一份小型 TOP10 服务结果。逻辑上至少包含：

- `data_version`：输入文件指纹与指标规则版本的组合，用于追溯；
- `rank`：1—10 的稳定排名；
- `diagnosis_name`：清洗后的主诊断描述；
- `case_count`：病例量，整数；
- `generated_at`：结果生成时间。

字段的具体命名、SQL 类型、唯一性和 API 映射由 #9 固定，本文不提前创造第二份契约。结果工件应记录输入文件名、文件指纹、规则版本和生成时间，但不得写入个人绝对路径。

刷新采用“先生成、后校验、事务装载”的方式：Spark 任务先生成下一批小结果，检查行数、排名连续性、排序和 `data_version`；MySQL 在事务中完成装载，任何失败都回滚，不能留下半批 TOP10。M1 只保留当前可服务批次，不提前建设历史结果仓库；需要历史对比时另建 Issue。

刷新失败时不得用前端写死数据或让 Flask 重新计算来掩盖失败。若数据库中已有上一批完整结果，可以继续明确标注其 `data_version`；若没有可用结果，API 返回依赖失败，页面进入错误态。

## 5. M0/M1 启动顺序

### M0：固定样本和契约并行开发

1. 在仓库根目录运行 `python data/src/verify_sparcs_mvp.py`，确认固定样本和独立期望结果一致。
2. 数据、后端和前端使用该固定结果做契约开发；前端 Mock 只能用于页面并行，不代表真实链路完成。
3. #9 固定服务结果字段、刷新和版本规则；#10 固定 API；#11 固定页面四态；#12 记录真实版本和依赖。

### M1：真实闭环

1. 准备本地完整 SPARCS CSV，先运行独立核对脚本。
2. 执行正式 Spark 任务，生成并校验小型 TOP10 结果工件。
3. 使用事务把结果工件装载到 MySQL，确认 `data_version` 和 10 条结果完整。
4. 启动 Flask，调用 #10 规定的健康检查和 TOP10 API。
5. 启动 Vue 页面，确认加载、正常、空数据和错误四种状态，以及名称、排名、病例量和单位。
6. 再运行独立脚本或 SQL 对原始输入与服务结果进行核对，记录命令和实际输出。

### 配置归属与目标端口

| 配置 | 归属 | 约定 |
|---|---|---|
| 输入 CSV 路径、结果工件路径、规则版本 | 数据任务命令行参数或数据侧本地配置 | 不写入个人绝对路径；示例使用占位符 |
| MySQL 主机、端口、库名、用户名和密码 | `backend/.env`，模板为 `backend/.env.example` | 真实 `.env` 不提交；默认端口目标为 3306 |
| Flask 监听地址和端口 | 后端启动参数/配置 | 默认目标为 5000，#12 负责实机确认 |
| 前端 API 基地址 | `frontend/.env.example` | 默认目标为 `http://localhost:5000`，由 #10/#12 交叉确认 |
| HDFS/Hive 地址 | 当前无 M1 配置 | 不因未使用组件增加环境变量 |

端口是当前最小方案的目标值，不是已经完成的环境验收；#12 必须以实际安装和启动结果为准。当前电脑的已查证状态为：Python 3.11.4 可运行，Node.js v22.13.1 可调用；`spark-submit`、`hdfs`、`hive` 和 `mysql` 命令未找到。完整 M1 因此不能在本次文档修改中宣称已启动，阻塞原因已明确交给 #12。

## 6. 故障和降级

| 故障 | M1 处理 | 允许的降级 |
|---|---|---|
| 原始 CSV 不存在、表头不符或解析异常 | 停止数据任务，不刷新 MySQL | 使用固定样本继续做契约和页面开发，但不称为真实闭环 |
| Spark 未安装或任务失败 | 标记数据任务阻塞，不用另一处偷偷重算 | 可用现有固定样本和独立脚本验证规则；正式全量结果待 Spark 恢复 |
| MySQL 不可用 | Flask 返回依赖失败，页面进入错误态 | 后端可使用固定 Mock 做接口开发；禁止静默改读另一份生产结果文件 |
| 结果为空但请求合法 | API 返回明确的空数据结构，页面进入空数据态 | 不把空结果改成错误，也不填充假数据 |
| Flask 不可用或请求格式错误 | 分别返回服务失败或请求错误；前端显示错误态 | 前端可用固定 Mock 继续开发四态 |
| HDFS/Hive/Pandas 不可用 | 不影响 M1，因为不在必要链路 | 保持当前方案，不安装无调用者的服务 |
| 前端 API 地址或端口错误 | 页面显示错误态，修正配置后重试 | 用 Mock 检查图表布局，不替代真实 API 验收 |
